## Phase 0 — Stabilize the Angular 5 baseline

- [ ] Resolve the split config: both `.angular-cli.json` (legacy) and `angular.json` (workspace format) currently exist — pick `angular.json`, delete the legacy file once confirmed unused
- [ ] Get `npm install` + `ng build` / `ng serve` working cleanly on current 5.2.3 with Node 8.9.x
- [ ] Confirm which git branch is the real "current prod" baseline before starting migration branches
- [ ] Commit a clean, green, bisectable baseline
- [ ] Remove stale `npm-debug.log` and other leftover artifacts
- [ ] Get a minimal Karma/Jasmine test run green as a regression baseline

## Phase 1 — Incremental `ng update`, one major at a time (5 → 12)

- [ ] **5 → 6**: `RouterModule.forRoot` config changes, `<template>` → `<ng-template>` rename, animations import changes
- [ ] **6 → 7**: low risk — CLI prompts, `budgets` in `angular.json`
- [ ] **7 → 8**: audit all 24 `@ViewChild`/`@ContentChild` usages for the required `static` flag; differential loading introduced
- [ ] **8 → 9**: **Ivy becomes default** — highest-risk single step pre-13. Check ag-grid 21.x and ngx-bootstrap 2.0 for Ivy compatibility; verify no code depends on ViewEngine internals
- [ ] **9 → 10 → 11 → 12**: incremental TypeScript bumps each step; by 12 you're on TS ~4.2–4.4 and can drop `es5` target
- [ ] Convert all 60 files using `rxjs/add/operator/...` patchable imports to pipeable operators (`from 'rxjs/operators'`) — do this before/during the 6→7 RxJS 6 bump
- [ ] Migrate the one legacy `Renderer` (v1) usage to `Renderer2`
- [ ] Re-evaluate `angular4-smart-table` (unmaintained) for replacement rather than upgrade
- [ ] Flag `moment.js` (13 files) for later replacement (Phase 3 cleanup)

## Phase 2 — Ivy maturity, standalone APIs, signals (13 → 17)

- [ ] **13**: View Engine fully removed — confirm all third-party libs are Ivy-only
- [ ] **14**: standalone components/directives/pipes available (optional adoption)
- [ ] **15**: standalone APIs stabilize; directive composition API
- [ ] **16**: signals introduced; `inject()`-based DI becomes idiomatic
- [ ] **17**: new control-flow syntax (`@if`/`@for`/`@switch`) replaces `*ngIf`/`*ngFor` — decide whether to do the template rewrite across all 365 files now or defer
- [ ] Decision point: full standalone conversion (drop NgModules) vs. keep NgModules — separate effort from the version bump itself
- [ ] Replace TSLint → ESLint via `@angular-eslint` schematics
- [ ] Replace Protractor → Cypress or Playwright for e2e

## Phase 3 — Land on 18 → 20.3.17

- [ ] **18**: zoneless change detection available as experimental (evaluate later, not required)
- [ ] **19**: continued signal API maturity
- [ ] **20.3.17**: final target — confirm TypeScript pinned to 5.8 or 5.9, Node 24.14.0
- [ ] Full regression pass: build, all views/forms, ag-grid tables, chart.js graphs, file-saver upload/download, ngx-bootstrap datepicker

## Parallel-track library migrations (thread through the phases above)

- [ ] `ag-grid-community` / `ag-grid-angular` 21.x → latest — check each major's own migration guide
- [ ] `ngx-bootstrap` 2.0 → latest, or evaluate `ng-bootstrap` as a replacement
- [ ] `chart.js` / `ng2-charts` 1.6 → latest (chart.js 2→3→4 each have breaking changes)
- [ ] `bootstrap` 4-beta → 5 (drops jQuery dependency — no jQuery usage currently, so this is clean)
- [ ] `zone.js` — version tracks Angular automatically via `ng update`
- [ ] `moment` → `date-fns` or native `Intl`/`Temporal` (optional cleanup)

## Process / tooling

- [ ] One branch per Angular major (`migration/angular-6`, `migration/angular-7`, …) — review individually, not as one diff
- [ ] CI: build + lint + test gate on every migration branch before merge
- [ ] Keep current prod branch deployable throughout — don't block production hotfixes on migration work
- [ ] Use `nvm`/Volta to switch Node per the table above at each phase transition
